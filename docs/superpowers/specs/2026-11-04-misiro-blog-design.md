## 1. 背景与目标

### 1.1 背景

参考站点 `blog.anheyu.com` 是一个功能密集的个人空间：文章、短文、友链、朋友圈、相册、音乐馆、小空调、弹幕、AI 摘要与播客。它的优势是信息密度和个性化，代价是后端依赖重、部署复杂、视觉语言强烈趋同（彩色圆角卡片 + 动漫插画 + 大圆角 + 音乐胶囊）。

本项目要做一个「神似而形不似」的技术博客：保留真正支撑阅读与内容分发的核心能力，砍掉需要后端、需要审核、需要长期运维的部分，并用一套完全独立的视觉语言重做。

### 1.2 目标

1. **国内可直接访问**：不依赖需要 ICP 备案的国内 CDN，同时保证可用的首屏速度。
2. **零后端、零数据库、零月费**：内容用 Git 管理，构建与托管全部走免费额度。
3. **视觉独立**：采用绝区零式的高对比街头 UI 语言，与原站的动漫卡片风格形成明确区隔。
4. **长文可读**：视觉冲击集中在首页与栏目标题，正文阅读区保持克制。
5. **可持续**：新增一篇文章 = 加一个 Markdown 文件 + push。

### 1.3 非目标

- 不做多用户、注册登录、权限体系。
- 不做在线编辑器与后台管理。
- 不做实时评论、弹幕、在线音乐播放。
- 不做 AI 摘要、AI 播客（涉及第三方 API 成本与内容合规）。

## 2. 设计原则

| 原则 | 含义 | 落到实现 |
| --- | --- | --- |
| 静态优先 | 能在构建期算出来的，绝不在运行时算 | 搜索索引、代码高亮、RSS、Sitemap 全部构建期生成 |
| 无后端 | 不引入数据库与服务进程 | 评论、统计、友链申请全部用外部轻量方案或静态数据 |
| 冲击力分层 | 首页负责「酷」，正文负责「读」 | 首页用海报式排版；文章页收敛为单列 680px |
| 少即是多 | 每个页面只保留一个主动作 | 首页主动作「读最新文章」，文章页主动作「读完/订阅」 |
| 可降级 | 视觉动效失败不影响阅读 | 动效只做增强，关闭后布局与信息不丢失 |

## 4. 架构设计

### 4.1 分层

```
┌─────────────────────────────────────────────────────────┐
│  内容层  content/posts · notes · albums · friends        │
│           Markdown / MDX + frontmatter（Zod 校验）        │
└───────────────────────────┬─────────────────────────────┘
                            │ 构建期读取
┌───────────────────────────▼─────────────────────────────┐
│  构建层  Astro 静态生成                                  │
│           ├─ Shiki 代码高亮（构建期）                     │
│           ├─ Pagefind 搜索索引（构建后产物）              │
│           ├─ Sharp 图片转 AVIF/WebP                      │
│           └─ RSS / Sitemap / OG 元数据                   │
└───────────────────────────┬─────────────────────────────┘
                            │ 静态产物 dist/
┌───────────────────────────▼─────────────────────────────┐
│  托管层  GitHub → Cloudflare Pages → 全球 CDN            │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  服务层  Cloudflare Web Analytics（无 Cookie 统计）       │
│          无后端 / 无数据库 / 无服务进程                    │
└─────────────────────────────────────────────────────────┘
```

### 4.2 构建流程

1. 本地写 Markdown，frontmatter 声明标题、日期、标签、分类、摘要、封面。
2. `git push` 到 GitHub 主分支。
3. Cloudflare Pages 触发构建：`pnpm install && pnpm build`。
4. 构建期依次执行：内容校验 → 页面生成 → 图片优化 → RSS/Sitemap；构建结束后执行 Pagefind 扫描产出搜索索引。
5. 产物上传 CDN，旧版本回滚由 Cloudflare 部署记录保证。

### 4.3 数据流

- **读取**：页面在构建期通过 `getCollection()` 读取内容集合，按 frontmatter 排序与过滤。
- **搜索**：Pagefind 在构建后扫描 `dist/`，生成分片索引；运行时由浏览器按需加载对应分片。
- **统计**：页面仅加载 Cloudflare Web Analytics 的 beacon 脚本，不采集个人身份信息。
- **友链申请**：页面上的按钮跳转到 GitHub Issue 模板，不经过本站服务端。

### 4.4 目录结构

```
misiro-blog/
├─ public/                    # 静态资源：图标、默认 OG 图、robots.txt
├─ src/
│  ├─ content/
│  │  ├─ posts/               # 文章 .md / .mdx
│  │  ├─ notes/               # 手记
│  │  ├─ albums/              # 相册元数据
│  │  └─ friends/             # 友链条目
│  ├─ components/             # 卡片、索引行、标签、灯箱、目录
│  ├─ layouts/                # 基础布局、文章布局
│  ├─ pages/                  # 路由
│  ├─ styles/                 # tokens.css、base.css、components.css
│  └─ lib/                    # 内容查询、日期格式化、SEO 工具
├─ astro.config.mjs
├─ tailwind.config.ts
├─ package.json
└─ docs/superpowers/specs/
```

### 4.5 关键取舍

| 取舍 | 选择 | 代价 |
| --- | --- | --- |
| 静态 vs 服务端渲染 | 静态 | 无法做实时数据，评论等动态能力缺失 |
| Astro vs Next.js | Astro | 生态组件少于 React 系，复杂交互需自己写 |
| 自建搜索 vs Pagefind | Pagefind | 中文分词精度一般，需靠标题权重补偿 |
| Cloudflare vs 国内云 | Cloudflare | 国内延迟不稳定，极端网络下可能较慢 |
| 无评论 vs giscus | 无评论 | 缺少读者反馈闭环 |

## 5. 技术选型

| 层 | 选型 | 版本策略 | 理由 |
| --- | --- | --- | --- |
| 框架 | Astro | 5.x | 默认零客户端 JS，岛屿架构适合内容站，构建快 |
| 语言 | TypeScript | 严格模式 | 内容 schema 与组件 props 可校验 |
| 样式 | Tailwind CSS + CSS 变量 | 4.x | 原子类提速，设计 token 集中在 CSS 变量 |
| 内容 | Markdown + MDX（按需） | — | 纯文本可迁移，不被平台锁定 |
| 校验 | Zod（Astro Content Collections） | 内置 | frontmatter 缺失直接构建失败，避免脏数据上线 |
| 搜索 | Pagefind | 1.x | 纯静态索引，零服务端，免费 |
| 高亮 | Shiki | Astro 内置 | 构建期高亮，无运行时 JS |
| 图片 | Astro `<Image>` + Sharp | — | 自动生成 AVIF/WebP 与多尺寸 |
| 图标 | 内联 SVG | — | 避免图标库体积与外部请求 |
| 部署 | Cloudflare Pages | 免费版 | 免备案、Git 自动部署、全球 CDN、无限带宽（合理使用） |
| 统计 | Cloudflare Web Analytics | 免费版 | 无 Cookie、不采集个人信息，无需同意横幅 |
| 动效 | 原生 View Transitions + CSS 动画 + Web Animations API | — | 零额外框架，可控体积，支持降级 |
| 包管理 | pnpm | 9.x | 安装快、磁盘占用低 |
| 代码质量 | ESLint + Prettier | — | 统一风格，提交前检查 |
| 测试 | Vitest + Playwright | — | 只测内容 schema、路由与关键交互 |

> 免费额度、备案与域名政策以平台当前条款为准，上线前需再次确认。

### 5.1 明确不引入

- UI 组件库（Ant Design / MUI 等）：视觉完全自定义，引入只会增加体积与改造成本。
- CSS-in-JS：运行时开销大，与静态优先冲突。
- 任何需要常驻服务或数据库的评论、统计、搜索方案。
- GSAP、Lenis 等动效与滚动劫持库：原生 View Transitions、CSS 动画与 WAAPI 已覆盖需求，避免额外体积与破坏滚动体验。

## 7. UI/UX 设计系统

### 7.1 视觉定位

关键词：**街头海报、粗描边、荧光黄绿、贴纸、网点、HUD 标注、CRT 残影**。

参考绝区零官网与游戏 UI 的「视觉母题」，但不使用其角色插画、Logo 与受版权保护的素材。所有装饰图形自绘为几何抽象元素。

### 7.2 色彩 Token

**深色（默认）**

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#0E0F12` | 页面底色 |
| `--bg-elevated` | `#16171B` | 面板、代码块底 |
| `--bg-elevated-2` | `#1E1F24` | 悬浮层、当前行 |
| `--text` | `#E7E6E1` | 正文 |
| `--text-muted` | `#8C8F96` | 元信息、说明 |
| `--line` | `rgba(231,230,225,.14)` | 分隔线 |
| `--accent` | `#D8FF3E` | 主强调、编号、按钮底 |
| `--accent-ink` | `#0E0F12` | 强调色上的文字 |
| `--accent-2` | `#34E0E0` | 次强调，仅图标与点缀 |
| `--accent-3` | `#FF3D81` | 贴纸、警示标签 |
| `--warning` | `#F5C518` | 黑黄警示条 |

**浅色**

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#F2F1EC` | 纸白底 |
| `--bg-elevated` | `#FFFFFF` | 面板 |
| `--text` | `#121316` | 正文 |
| `--text-muted` | `#5C5F66` | 元信息 |
| `--accent` | `#D8FF3E` | 仅用于色块与图形 |
| `--accent-text` | `#5A6B00` | 浅色模式下可读的强调文字 |

**使用约束**

- 荧光黄绿只用于大字号、图形、色块和按钮底；正文永不使用该色。
- 强调色上必须用 `--accent-ink` 黑字，禁止白字。
- 品红与电青各自在一屏内占比不超过 5%。
- 所有正文对比度 ≥ 4.5:1，元信息 ≥ 3:1。

### 7.3 字体

| 角色 | 字体 | 回退 | 说明 |
| --- | --- | --- | --- |
| 展示标题 | Archivo Black | 思源黑体 900 | 开源 OFL，自托管子集，仅拉丁字符 |
| 中文标题 | 思源黑体 900 | 系统黑体 | 自托管子集，控制体积 |
| 正文 | 系统 UI 无衬线 | PingFang SC / 微软雅黑 | 零下载成本，中文长文最稳 |
| 标注与编号 | JetBrains Mono | ui-monospace | 开源 OFL，数字与英文标注 |

**字号阶梯**

| 角色 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| Display | `clamp(40px, 6vw, 88px) / 1.02` | 首页 Hero 标题 |
| H1 | `48px / 1.15` | 文章标题 |
| H2 | `32px / 1.3` | 章节标题 |
| H3 | `24px / 1.4` | 小节标题 |
| Body | `17px / 1.75` | 正文 |
| Caption | `13px / 1.6` | 元信息、脚注 |
| Mono | `12px / 1.5` | 编号、标签、时间 |

### 7.4 版式与网格

- 最大内容宽 `1280px`，左右安全边距 `clamp(20px, 5vw, 64px)`。
- 桌面端 12 列网格，列间距 24px；移动端退化为单列，间距 16px。
- 首页采用 7 / 5 的不对称分栏（主内容 / 精选侧栏）。
- 文章正文单列 `680px`，目录固定在右侧 `220px`，两者间距 64px。
- 全局圆角：`0` 为主，输入框与按钮 `2px`，胶囊按钮 `999px`。

### 7.5 核心组件

| 组件 | 规格 |
| --- | --- |
| Hero 标题 | 黑体 900，1–2° 倾斜，字距 `-0.02em`，下方 4px 荧光色块 |
| 贴纸标签 | 白底黑边 2px、旋转 ±3°、内边距 6/12、投影为纯色偏移而非模糊 |
| 警示条 | 黑黄 45° 斜纹，高 10px，用于「最新 / 精选 / 施工中」 |
| 编号索引行 | `001` 等宽编号 + 标题 + 标签 + 日期，行间 1px 细线，无卡片 |
| HUD 角标 | 10px 十字与刻度线，仅出现在区块四角 |
| 网点底纹 | 4px 间距圆点，透明度 6%，仅用于 Hero 与页脚 |
| 目录 | 等宽编号 + 当前项左侧 3px 荧光竖条 |
| 代码块 | 深底、顶部语言标签与复制按钮、行号可选 |
| 灯箱 | 黑色遮罩 92%、图片居中、左右键翻页、底部 caption |

### 7.6 动效系统

动效不是点缀，而是这套视觉语言的一部分。目标是「丝滑、连续、有记忆点」，但绝不打断阅读。

#### 7.6.1 四条原则

| 原则 | 说明 |
| --- | --- |
| 三层强度 | 品牌层（首页首屏、路由切换、404）可以强；内容层（阅读、目录）只在必要时动；反馈层（按钮、复制）必须快，≤160ms |
| 连续感 | 全站共用一套缓动与时长；路由切换不出现白屏，旧页与新页有明确的方向关系 |
| 主题一致 | 只允许位移、遮罩擦除、扫描线、网点、描边、RGB 错位这几类动作；禁止弹性缩放、模糊光晕、漂浮粒子等与主题无关的效果 |
| 性能红线 | 只动画 `transform` / `opacity` / `clip-path`；单帧并行动画 ≤ 3 个；首屏入场总时长 ≤ 900ms；动画期间可交互元素立即可点 |

#### 7.6.2 时长与缓动 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--dur-1` | `80ms` | Hover、按下 |
| `--dur-2` | `120ms` | 淡入淡出、焦点反馈 |
| `--dur-3` | `200ms` | 路由切换主体、抽屉 |
| `--dur-4` | `320ms` | 贴纸弹入、灯箱 |
| `--dur-5` | `480ms` | 首屏扫描线开幕 |
| `--ease-expo` | `cubic-bezier(.16, 1, .3, 1)` | 路由切换、擦除 |
| `--ease-quart` | `cubic-bezier(.25, 1, .5, 1)` | 位移、揭示 |
| `--ease-inout` | `cubic-bezier(.65, 0, .35, 1)` | 开合、对称过渡 |
| `--ease-spring` | `cubic-bezier(.34, 1.56, .64, 1)` | 贴纸、磁吸回位 |
| `--stagger` | `40ms` | 列表与字符编排间隔 |

#### 7.6.3 场景编排

**A. 首屏入场（仅首次会话，`sessionStorage` 记录）**

1. `0–80ms`：页面底色先到位，内容整体 `opacity: 0`，避免闪现。
2. `80–560ms`：扫描线开幕——1px 荧光横线自上而下扫过，遮罩随之退去（`480ms`，`--ease-expo`）。
3. `320–560ms`：Hero 标题按行 `clip-path: inset(0 0 100% 0)` 揭示，逐行 `60ms` 间隔，`--ease-quart`。
4. `440–760ms`：贴纸标签 `scale(.92) → 1`、`rotate(6deg) → 3deg`，`--ease-spring`。
5. `560–900ms`：文章索引行 `translateY(12px) + opacity` 依次进入，最多 6 行，`40ms` 间隔。
6. 进入完成后不再重复任何循环动画。

**B. 路由切换**

- 使用原生 View Transitions；旧页 `translateY(-6px)` + 透明度降至 0，`120ms`；新页 `clip-path: inset(0 0 100% 0) → inset(0)`，`200ms`，`--ease-expo`。
- 顶部 1px 荧光线同步从左扫到右，作为方向提示。
- 列表 → 详情使用共享元素：文章封面或标题的 `view-transition-name` 由列表与详情页同时声明。
- 切换期间锁定滚动，结束后焦点移动到页面主标题（`tabindex="-1"`），保证键盘用户不迷失。
- 不支持 View Transitions 的浏览器降级为 120ms 淡入，不出现布局跳动。

**C. 阅读流**

| 场景 | 表现 | 实现 |
| --- | --- | --- |
| 阅读进度条 | 顶部 2px 荧光条随滚动增长，无回弹 | CSS `animation-timeline: scroll()`，JS 降级为 `scroll` 事件节流 |
| 目录高亮 | 当前项左侧 3px 竖条高度过渡，不跳色 | `height` 改为 `scaleY` 避免布局，`160ms` |
| 章节标题揭示 | 进入视口时下划线从左展开，仅触发一次 | IntersectionObserver 加 class |
| 锚点跳转 | 平滑滚动并预留 96px 顶部偏移 | `scroll-behavior: smooth` + `scroll-margin-top` |
| 代码复制 | 按钮文字切为 `COPIED` 并描边闪一次 | `80ms`，2 秒后复位 |

**D. 反馈层（≤160ms）**

| 元素 | 表现 |
| --- | --- |
| 索引行 / 文章卡 | 左移 4px，标题下荧光下划线展开，`80ms` |
| 贴纸 | 回正到 0°、放大 1.02，`100ms`，`--ease-spring` |
| 主按钮 | 荧光色块自左向右滑入，文字保持深色以保证对比，`120ms` |
| 磁吸按钮 | 光标 12px 范围内按钮位移最多 6px，离开回位，`200ms` |
| 标题 Hover | 单次 RGB 错位：青/品红伪元素各偏移 2px，`60ms` 后复位，每次 Hover 只触发一次 |

**E. 沉浸层**

| 场景 | 表现 |
| --- | --- |
| 搜索层 | 从顶部输入框位置 `scaleY(.96) + opacity` 展开，`--ease-quart`，`160ms`；关闭反向 `120ms` |
| 移动端导航抽屉 | 从右侧擦入，`200ms`，背景网点遮罩淡入 |
| 相册灯箱 | FLIP：缩略图位置 → 全屏，`240ms` `--ease-expo`；关闭反向 `200ms` |
| 404 | 数字「404」入场时横向错位 2px 三次，`180ms` 后静止，不循环 |
| 页脚网点 | 随滚动位移 8px 的轻视差，仅桌面端，滚动停止即停 |

**F. 环境特效（只在首页 Hero，桌面端）**

- 指针聚光：一层 8% 透明度的径向光跟随光标，`requestAnimationFrame` 节流，离开 Hero 即淡出。
- 该效果与磁吸按钮、RGB 错位共同构成「酷」的部分，但全部限定在首屏，文章页一律不出现。

#### 7.6.4 降级与可访问性

| 条件 | 处理 |
| --- | --- |
| `prefers-reduced-motion: reduce` | 关闭位移、错位、视差、聚光与扫描线；仅保留 ≤120ms 的透明度变化 |
| 触屏 / `pointer: coarse` | 关闭聚光与磁吸，保留点击反馈 |
| `navigator.connection.saveData` 或低端设备 | 关闭聚光、视差与共享元素过渡 |
| 页面切到后台 | 暂停所有有限动画，避免回到前台时集中播放 |
| 键盘操作 | 焦点环不参与动画；焦点移动即时生效，不等动画结束 |

#### 7.6.5 实现方式

- 路由与共享元素：Astro `<ClientRouter />` + 自定义 `::view-transition-old/new` keyframes。
- 入场编排：CSS keyframes + `animation-delay`；需要逐字符或复杂序列时用 Web Animations API，不引入 GSAP。
- 滚动驱动：优先 CSS `animation-timeline`，Safari 旧版用 IntersectionObserver 降级。
- 不引入 Lenis 等滚动劫持库：原生 `scroll-behavior` 已足够，劫持会破坏可访问性与低端设备体验。
- 动效代码预算：新增 JS ≤ 8KB（gzip），全部动效参数集中写在 `tokens.css`，组件不写魔法数字。

#### 7.6.6 动效验收

- 首屏入场在 6 倍 CPU 降速下仍 ≥ 50fps。
- 路由切换无白屏、无布局跳动、无滚动位置错乱。
- 单页同时运行的动画不超过 3 个。
- 开启「减少动态效果」后，全站可正常阅读与操作，信息不丢失。

### 7.7 响应式

| 断点 | 行为 |
| --- | --- |
| `< 640px` | 单列；Hero 标题降至 40px；导航收进全屏抽屉 |
| `640–1024px` | 文章列表单列；目录折叠为顶部按钮 |
| `> 1024px` | 启用不对称分栏与右侧目录 |

### 7.8 可访问性

- 全站键盘可达，焦点环为 2px 荧光描边 + 2px 偏移。
- 图片必须有 `alt`，装饰性图形 `aria-hidden`。
- 不依赖颜色传达信息，标签同时带文字。
- 灯箱与搜索层实现焦点陷阱与 `Esc` 关闭。
- 深色模式为默认，提供浅色模式切换并写入 `localStorage`。

## 8. 页面规格

### 8.1 首页 `/`

```
顶栏：Logo / 文章 归档 标签 手记 / 搜索 / 主题切换
01 Hero：左（栏目标签 + 主标题 + 副标题 + 两个按钮 + 统计）
        右（本周精选 dossier 面板）
02 刻度线分隔
03 全部文章（编号索引 5–8 条 + 更多入口）
04 双栏：手记摘要 / 标签矩阵 + RSS
页脚：站点信息 + 社交 + 版权
```

- 主动作：读最新文章。
- 精选由 `featured: true` 决定，最多 1 篇。
- 统计项：文章数、总字数、起始年份，构建期计算。

### 8.2 文章详情 `/posts/[slug]`

- 顶部：面包屑 → 分类 → 标题 → 日期 / 阅读时长 / 标签。
- 正文：单列 680px，首段前显示 frontmatter 中手写的 `description` 摘要（不使用 AI 生成）。
- 右侧粘性目录，滚动高亮当前章节。
- 顶部 2px 阅读进度条。
- 文末：版权声明、上一篇 / 下一篇、相关文章（同标签最多 3 篇）。
- 无评论区；文末提供 RSS 订阅入口。

### 8.3 归档 `/archives`

- 按年份分组，年份用 Display 字号。
- 每年下为编号索引行，右侧显示月份。
- 顶部提供年份快速跳转。

### 8.4 分类与标签

- 分类页：清单式，每行「分类名 + 文章数 + 最新一篇标题」。
- 标签页：标签矩阵，字号随文章数三档变化，不使用彩色胶囊。
- 详情页：复用编号索引行。

### 8.5 搜索 `/search`

- 顶部大号输入框，占位「输入关键词，回车搜索」。
- 结果行：类型徽标（文章 / 手记）+ 标题 + 摘要 + 日期。
- 空态给热门标签；无结果显示「没有找到，换个词试试」。
- 首屏不加载索引，聚焦输入后才按需拉取 Pagefind 分片。

### 8.6 手记 `/notes`

- 时间倒序短内容流，每条为「日期 + 正文 + 可选单图」。
- 条目间用细线分隔，不使用卡片。
- 单条超过 6 行折叠，展开不跳页。

### 8.7 相册 `/albums`

- 顶部相册封面与标题，点击进入图片墙。
- 灯箱支持左右箭头与键盘翻页，显示序号与 caption。
- 缩略图使用固定比例裁切，避免抖动。

### 8.8 友链 `/friends`

- 分组展示，每项为「头像 + 名称 + 一句话 + 域名」。
- 顶部按钮「申请友链」跳 GitHub Issue 模板。
- 页面注明审核标准与响应时间预期。

### 8.9 关于 `/about` 与项目 `/projects`

- 关于：一段自我介绍、技能标签、时间线、联系方式。
- 项目：编号列表，每项含名称、一句话、技术栈、仓库 / 线上链接。

### 8.10 404

- 大号「404」+ 一句自嘲文案 + 搜索框 + 返回首页。
- 保持站点视觉语言，不跳转外链。

## 9. 性能、SEO 与运维

### 9.1 性能预算

| 指标 | 目标 |
| --- | --- |
| 首屏 JS（gzip） | < 60KB（含动效代码 ≤ 8KB） |
| LCP（国内，4G） | < 2.5s |
| 图片 | AVIF 优先，单图 < 200KB |
| 字体 | 子集化，总计 < 80KB |
| Lighthouse 性能 | ≥ 90 |

### 9.2 SEO

- 每页唯一 `title` / `description` / canonical。
- 文章页输出 `BlogPosting` JSON-LD。
- OG 图优先使用文章封面，缺省用站点默认图。
- 自动生成 `sitemap-index.xml`、`rss.xml`、`robots.txt`。

### 9.3 运维

- 部署失败可在 Cloudflare 控制台一键回滚到上一版本。
- 内容错误由 Zod 在构建期拦截，不会带病上线。
- 每季度检查依赖与 Node 版本，避免构建环境过期。

## 10. 风险与权衡

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Cloudflare 国内延迟波动 | 首屏偏慢，个别地区抽风 | 控制资源体积；二期可用 EdgeOne Pages 默认域名做镜像 |
| 荧光色可读性 | 长时间阅读疲劳 | 强调色只用于标题与图形，正文用暖白 |
| 绝区零视觉版权 | 法律风险 | 只借鉴排版与图形语言，不使用角色、Logo、官方素材 |
| 中文字体体积 | 首屏字体加载慢 | 只自托管标题字重子集，正文用系统字体 |
| Pagefind 中文分词 | 搜索结果精度一般 | 标题、标签提权；摘要截断展示 |
| 无评论 | 缺少反馈 | 引导到 GitHub Issue 或邮件；二期可接 giscus |
| 单一托管商 | 服务中断 | 静态产物可随时迁移到任意静态托管 |

## 11. 验收标准（一期）

1. `pnpm build` 零错误，Zod 校验覆盖全部内容类型。
2. 首页、文章页、归档、标签、搜索、手记、相册、友链、关于、404 全部可访问。
3. 搜索能在 200ms 内返回本地结果，无网络请求失败阻塞。
4. 文章页目录高亮、代码复制、阅读进度正常。
5. 移动端 375px 宽度无横向滚动，导航抽屉可用。
6. 深色 / 浅色切换持久化，刷新不闪白。
7. Lighthouse 性能 ≥ 90、可访问性 ≥ 90。
8. RSS 与 Sitemap 可被有效解析。
9. 全站无第三方 JS，仅统计脚本一个外部请求。
10. 新增一篇文章只需添加 Markdown 并 push，无需改代码。
11. 首屏入场动画在 6 倍 CPU 降速下仍 ≥ 50fps，无跳动、无遮挡阅读。
12. 路由切换无白屏与布局跳动，共享元素在支持 View Transitions 的浏览器中正确衔接。
13. 开启 `prefers-reduced-motion` 后，全站功能完整、可正常阅读。
