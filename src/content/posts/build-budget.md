> 预算不是上线前的检查表，而是设计阶段的约束条件。等到 Lighthouse 变红再回头，通常已经来不及了。

这篇文章记录我给 MISIRO 定预算的过程。目标很明确：一个没有后端、没有数据库、只靠 Git 推送的个人技术博客，在国内普通 4G 网络下也要在两秒半内完成首屏。

## 为什么先写预算

静态站点的性能问题，很少是「服务器太慢」，更多是「什么都想要」。字体想要三套，动效想要丝滑，图片想要高清，代码块想要彩色主题。每一项单看都合理，叠加起来就超支。

所以我把预算写成硬性数字，并且让构建过程无法绕开它：

| 项目 | 红线 | 测量方式 |
| --- | --- | --- |
| 首屏 JS | < 60KB gzip | 构建产物统计 |
| 动效代码 | < 8KB gzip | 单独统计脚本块 |
| LCP | < 2.5s | 国内 4G 模拟 |
| 单张图片 | < 200KB | AVIF 优先 |
| 字体总量 | < 80KB | 仅首屏用到的子集 |

预算一旦写下来，技术选型就有了取舍依据。比如动效库 GSAP 压缩后接近 70KB，直接出局；滚动劫持库 Lenis 同样不进入候选。原生 View Transitions 加 CSS 动画足够覆盖需求，而且不增加额外运行时。

### 从构建期拿走一切能拿走的

能在构建期算出来的，就不要留给浏览器：

```ts
// 构建期计算字数与阅读时长，运行时不做任何统计
const plain = body.replace(/```[\s\S]*?```/g, ' ');
const cjk = (plain.match(/[\u4e00-\u9fff]/g) ?? []).length;
const minutes = Math.ceil(cjk / 350);
```

代码高亮同理。Shiki 在构建阶段把 Markdown 变成带颜色的 HTML，浏览器拿到的只是普通标记，不需要下载高亮引擎。

## 字体是最大的隐性成本

中文字体是首屏最容易失控的部分。一套完整的思源黑体，动辄几 MB。我的做法是：

1. 展示字体只自托管拉丁字符，Archivo Black 一个字重就够。
2. 中文标题使用 Noto Sans SC 的 unicode-range 子集，浏览器只下载页面实际用到的字形。
3. 正文完全使用系统 UI 字体，零下载成本，中文长文最稳。

> 系统字体不是妥协，而是对长文阅读最诚实的选择。读者不会因为你用了自定义字体而多读两段。

### 动效也要计费

动效代码预算是 8KB。为了守住这条线，我只使用三类能力：

- CSS keyframes：首屏入场、下划线展开
- Web Animations API：需要精确编排的序列
- View Transitions：路由切换与共享元素

所有时长和缓动集中在 `tokens.css`，组件里不准出现魔法数字。这样既统一了节奏，也让「减少动态效果」的降级只需要改一处。

## 一个具体的取舍

首页原本想做指针聚光、磁吸按钮、RGB 错位三种环境特效。三者在同一帧里同时运行时，低端设备的帧率会掉到 40 以下。

最后的方案是：聚光与磁吸只在桌面端、只在首屏出现；RGB 错位只在标题 Hover 时触发一次，60ms 后复位。三者永远不同时启动，单帧并行动画不超过三个。

```css
@media (pointer: coarse), (prefers-reduced-motion: reduce) {
  .spotlight { display: none; }
}
```

## 收尾

预算真正的作用，是让你在写第一行代码之前就知道哪些东西不能要。构建不是交付前的杂活，它本身就是作品的一部分。
